OpenAI launches GPT-6.2 Astra and Sol with lower API prices and some benchmark gains

OpenAI เปิดตัว GPT-6.2 Astra สำหรับงานมืออาชีพด้านวิทยาศาสตร์ กฎหมาย และการเงิน และ GPT-6.2 Sol สำหรับงานทั่วไปที่ต้องการความเร็ว ราคา API ของ Astra อยู่ที่ $8 ต่อล้าน input token และ $40 ต่อล้าน output token ถูกลง 20% ส่วน Sol คงราคา $2/$10 OpenAI อ้างว่า Astra ทำคะแนน Agents' Last Exam สูงกว่า GPT-6 Astra 5.2 คะแนนด้วยต้นทุนไม่ถึงหนึ่งในสาม Artificial Analysis จัด Astra อันดับสองใน Intelligence Index ที่ 62 คะแนน รองจาก Claude Fable 5.2 ที่ 65 และนำ Gemini 4 Carbon ที่ 60 แต่พบอัตรา hallucination 59% สำหรับ Astra และ 55% สำหรับ Sol ใน AA-Omniscience ด้าน Epoch AI ให้ Astra 174 คะแนนเท่ากับ Fable 5.2 และแก้โจทย์ FrontierMath Erdős ได้ 7 จาก 68 ข้อ ที่สำคัญ OpenAI ระบุว่าทั้งสองโมเดลแตะเกณฑ์ Critical ด้านไซเบอร์ และ Astra เป็นโมเดลแรกที่ถึงระดับ High ด้าน AI self-improvement จึงเพิ่มการเฝ้าระวังผ่านระบบ Control Room

K2-Horizon: ฝูงโมเดลภาษาโอเพนซอร์สระดับ frontier

K2-Horizon: A Frontier Fleet of Open Source Language Models

ทีม K2 จาก Institute of Foundation Models หรือ IFM เปิดตัว K2-Horizon ตระกูลโมเดลภาษาแบบเปิดเต็มรูปแบบ 6 รุ่น ตั้งแต่โมเดล dense ขนาด 0.9B ไปจนถึงโมเดล MoE ขนาดรวม 375B ที่มีพารามิเตอร์ทำงานจริง 23B ออกแบบสำหรับงาน reasoning และ agentic ด้านคณิตศาสตร์ วิทยาศาสตร์ วิศวกรรมซอฟต์แวร์ deep research และงานสำนักงานอัตโนมัติ โดยทำคะแนนเทียบเท่าหรือนำโมเดลเปิดระดับเดียวกันใน benchmark ด้าน agent และการเขียนโค้ด ทีมนำเสนอ Mixture-of-Value Attention หรือ MoVA ที่นำ MoE ไปใช้กับ value projection ของ attention พร้อม softplus attention gate ซึ่งทำให้โมเดล 36B-A4B ได้ผลใกล้เคียงโมเดล dense 32B ที่ฝึกด้วยข้อมูลเดียวกัน โดยใช้พารามิเตอร์ทำงานเพียงหนึ่งในเจ็ด และยังเสนอ Uno ตัวปรับแบบ diffusion ที่เร่งการถอดรหัสได้ถึง 2.2 เท่าโดยไม่ต้องใช้ draft model การเผยแพร่ยึดมาตรฐาน LLM360 ครบทั้ง checkpoint ระหว่างทาง ข้อมูล pre-training ราว 22T token log การฝึก และโค้ด

Tech Impact: โมเดลเปิดแบบโปร่งใสเต็มรูปแบบระดับ frontier ช่วยให้นักวิจัยและองค์กรศึกษา ปรับแต่ง และ self-host ได้โดยไม่ติดข้อจำกัดของโมเดลปิด

👩‍💻 Developer

  • ทดลองโมเดลขนาดเล็กของ K2-Horizon สำหรับ on-premise inference และ fine-tune ภาษาไทย
  • ศึกษาเทคนิค MoVA และ Uno เพื่อลดต้นทุน inference ของโมเดลที่ใช้อยู่

💼 Business

  • พิจารณาโมเดลเปิดเป็นทางเลือกสำหรับงานที่ต้องเก็บข้อมูลไว้ภายในองค์กร
  • ประเมินต้นทุนรวมของการ self-host เทียบกับการใช้ API

ScaleVLA: ขยายโมเดล Vision-Language-Action สู่ 552 พันล้านพารามิเตอร์

ScaleVLA: Scaling Vision-Language-Action Models to 552 Billion Parameters

ทีมวิจัยจาก Galbot ตั้งคำถามว่า representation จากโมเดล vision-language ขนาด frontier จะเป็นฐานที่แข็งแรงกว่าสำหรับนโยบายควบคุมหุ่นยนต์หรือไม่ เนื่องจากโมเดล VLA ส่วนใหญ่ใช้ backbone ขนาดเล็ก จึงพัฒนา ScaleVLA ที่เชื่อม backbone DeepSeek-V4.1-Flash ขนาด 552B พารามิเตอร์เข้ากับ action diffusion transformer ที่ฝึกได้ และเปรียบเทียบ VLM ตั้งแต่ 2B ถึง 552B ผลคือเมื่อใช้ตัวอย่างสาธิตเพียง 10 ครั้ง ScaleVLA ทำอัตราสำเร็จได้ 87.8% สูงกว่า backbone 2B ที่ใช้ตัวอย่าง 50 ครั้งซึ่งได้ 85.6% บน LIBERO-PRO ซึ่งวัดการ generalize ได้ 45.1% เทียบกับไม่เกิน 31.3% ของโมเดลเล็ก ในงานจริงอย่างการเสียบหัวชาร์จ อัตราสำเร็จเพิ่มจาก 4 ใน 10 เป็น 9 ใน 10 โดยเฉพาะการจัดตำแหน่งที่ต้องอาศัยการสัมผัส แม้มีขนาดใหญ่ แต่ latency มัธยฐานอยู่ที่ 216 มิลลิวินาทีต่อ action chunk ผู้วิจัยสรุปว่า VLM ระดับ frontier เป็นฐาน representation ที่ทรงพลังสำหรับหุ่นยนต์ ไม่ได้เป็นเพียง reasoning agent

Tech Impact: หลักฐานว่า scaling ของ backbone ช่วยลดจำนวนตัวอย่างสาธิตที่หุ่นยนต์ต้องใช้ อาจเร่งการนำ physical AI ไปใช้ในงานอุตสาหกรรมที่ข้อมูลฝึกหายาก

👩‍💻 Developer

  • ทดลองใช้ VLM ขนาดใหญ่เป็น frozen backbone ร่วมกับ action head ขนาดเล็กสำหรับงานหุ่นยนต์
  • วัด latency ต่อ action chunk ให้เหมาะกับงานควบคุมแบบ real-time

💼 Business

  • ประเมินโอกาสใช้หุ่นยนต์ few-shot ในสายการผลิตที่งานเปลี่ยนบ่อย
  • จับตาต้นทุน compute ของการ deploy VLA ขนาดใหญ่ในโรงงาน

SWE-CoWork: Benchmarking Coding Agents as Digital Employees in Organizations

งานวิจัย SWE-CoWork เสนอ benchmark ใหม่ที่ประกอบด้วยงานพัฒนาซอฟต์แวร์ 101 งานจาก repository จริง 101 แห่ง ครอบคลุม 11 ภาษาโปรแกรมและ 12 โดเมน แต่ละงานจำลองให้ coding agent ทำงานในองค์กรวิศวกรรมที่มีเพื่อนร่วมงาน 26 คนซึ่งมีหน้าที่และความรู้แตกต่างกัน agent เริ่มจากบันทึกส่งมอบงานสั้น ๆ แล้วต้องรวบรวม requirement ที่กระจายอยู่ตามเพื่อนร่วมงานและเอกสาร แก้ข้อมูลที่ขัดแย้ง และเขียนโค้ดที่ตรวจด้วย test ลับ จากการทดสอบ 11 โมเดล สองโมเดลชั้นนำผ่าน fail-to-pass test ราว 63% แต่ทำงานสำเร็จทั้งชิ้นได้ไม่ถึง 8% การให้ requirement ครบตั้งแต่ต้นช่วยเพิ่มคะแนน test ราว 16 จุด แต่ไม่เปลี่ยนอัตราความสำเร็จโดยรวม การวิเคราะห์พบว่า Claude-Opus-5.5 ถามคำถามแรกถูกคนถึง 93% แต่ได้ requirement จากเพื่อนร่วมงานเพียง 64% และ 31% ของ requirement ที่รายงานว่าเสร็จกลับไม่ผ่าน test ผู้วิจัยสรุปว่าการติดตาม requirement ตลอดกระบวนการคืออุปสรรคหลักของวิศวกรรมซอฟต์แวร์อัตโนมัติ

Tech Impact: ชี้ว่าช่องว่างของ coding agent ไม่ได้อยู่ที่การเขียนโค้ดแต่อยู่ที่การสื่อสารและติดตาม requirement ในองค์กร ซึ่งสำคัญต่อการนำ agent มาใช้แทนพนักงาน

👩‍💻 Developer

  • ให้ agent เขียน checklist ของ requirement และตรวจกับ test ก่อนรายงานว่างานเสร็จ
  • เชื่อม agent กับแหล่ง requirement จริง เช่น ticket และเอกสาร แทนการพึ่ง prompt สั้น

💼 Business

  • ตั้งความคาดหวังต่อ coding agent ให้เหมาะสม โดยใช้กับงานที่ requirement ชัดเจน
  • วางกระบวนการ review ของมนุษย์สำหรับงานที่ต้องประสานหลายฝ่าย

SPILLWAY: Separating Target Admission from Sanitization to Defend Tool-Using Agents against Prompt Injection

Agent ที่ใช้เครื่องมือจัดการอีเมล ไฟล์ และการชำระเงิน อาจถูกยึดการควบคุมด้วยคำสั่งที่ซ่อนอยู่ในหน้าเว็บหรือเอกสาร จนส่งข้อมูลหรือเงินให้ผู้โจมตี วิธีป้องกันเดิมจำนวนมากใช้โมเดลภาษาอนุมัติแต่ละ action ซึ่งอาจถูกข้อความของผู้โจมตีชักนำได้และเพิ่มจำนวนการเรียกโมเดล งานวิจัย SPILLWAY จาก SAINT Machines จึงใช้การตรวจแบบ deterministic โดยอ่านเป้าหมายของ action จาก typed field ที่เครื่องมือแบบอ่านอย่างเดียวส่งคืน เช่น ผู้ส่งอีเมลหรือบัญชีรับเงิน เพราะคำสั่งแฝงมักมาในรูปข้อความอิสระ การเรียกใช้จะผ่านเมื่อเป้าหมายใหม่มาจาก typed field หรือตรงกับกฎมอบหมายที่กำหนดไว้ ผลทดสอบกับ 3 backbone และ 7 ชุดงาน ไม่มีการโจมตีแบบ templated ใดเปลี่ยนเป้าหมายไปยังผู้โจมตีได้ อัตราสำเร็จของผู้โจมตีที่ฝึกด้วย reinforcement learning เฉลี่ยเพียง 0.007 และรักษา utility ได้สูงสุดในกลุ่มวิธีที่เปรียบเทียบ

Tech Impact: แนวทางป้องกัน prompt injection แบบ deterministic ที่แทบไม่เพิ่มการเรียกโมเดล อาจกลายเป็นรูปแบบมาตรฐานสำหรับ agent ที่แตะเงินหรือข้อมูลสำคัญ

👩‍💻 Developer

  • กำหนดให้เป้าหมายของ action สำคัญต้องมาจาก typed field ที่ตรวจสอบได้ ไม่ใช่ข้อความอิสระ
  • แยกขั้นกรองข้อความภายนอกออกจากขั้นอนุญาต action ในสถาปัตยกรรม agent

💼 Business

  • กำหนดนโยบายว่า agent ห้ามโอนเงินหรือส่งข้อมูลไปยังปลายทางที่ไม่อยู่ใน allowlist
  • ประเมินความเสี่ยง prompt injection ก่อนนำ agent ไปใช้กับระบบการเงิน

สำนักงานอุตสาหกรรมและความมั่นคงของสหรัฐฯ หรือ BIS ออกกฎชั่วคราวเพื่อปิดช่องโหว่ที่บริษัทจีนเช่าพลังประมวลผล Nvidia จากศูนย์ข้อมูลต่างประเทศ ผู้ให้บริการในสิงคโปร์ มาเลเซีย ไทย อินโดนีเซีย และบราซิล จะต้องขอใบอนุญาตจากรัฐบาลสหรัฐฯ ก่อนซื้อชิป AI ขั้นสูง โดยพิจารณาเป็นรายกรณี ยกเว้นบริษัทลูกของบริษัทสหรัฐฯ หุ้น Nvidia ร่วงสูงสุด 2.9% และดัชนี Philadelphia Semiconductor ลดลงถึง 5.5% มาตรการนี้ตามมาหลังการลาออกกะทันหันของ Jensen Huang และการสอบสวน Megaspeed International ในสิงคโปร์ ขณะเดียวกัน Reuters วิเคราะห์เอกสารจีนกว่า 300 ชิ้น พบว่าจีนพึ่ง model distillation อย่างหนัก โดยดึงคำตอบและโค้ดจากโมเดลสหรัฐฯ อัตโนมัติมาฝึกโมเดลขนาดเล็ก เช่น โครงการของมหาวิทยาลัย Shanghai Jiao Tong ปี 2024 ที่สร้างตัวอย่าง 10,750 รายการให้ Qwen2.5-72B จากคำตอบของ o1 ราว 5,000 รายการ การกลั่นโมเดลไม่ผิดกฎหมายแต่ละเมิดเงื่อนไขการใช้งาน และ Scott Bessent ขู่ใช้มาตรการคว่ำบาตรหากเข้าข่ายขโมยทรัพย์สินทางปัญญา
