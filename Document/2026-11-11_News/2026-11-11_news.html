Introducing AlphaProof Code: a breakthrough in verifying complex software at depth
DeepMind เปิดตัว AlphaProof Code ใช้ AI พิสูจน์ความปลอดภัยของโปรโตคอล Signal ระดับโค้ดจริง
Google DeepMind เปิดตัว AlphaProof Code เฟรมเวิร์ก agent ที่ใช้หลายโมเดลร่วมกัน เพื่อพิสูจน์เชิงรูปนัย (formal verification) คุณสมบัติด้านความปลอดภัยสำคัญของโค้ดโปรโตคอล Signal ซึ่งใช้เข้ารหัสข้อความในแอป Signal และ Google Messages โดยนักวิจัยแปลงเป้าหมายด้านความปลอดภัยเป็นข้อกำหนดเชิงรูปนัยที่ผู้เชี่ยวชาญตรวจทาน จากนั้น agent ที่ใช้ Gemini Carbon เขียนบทพิสูจน์ในภาษา Lean รวมกว่า 6 ล้านบรรทัดตามเนื้อหาหลัก (คำอธิบายย่อของหน้าระบุ 3 ล้านบรรทัด) ภายในเวลา 4 สัปดาห์ ซึ่งปกติต้องใช้ทีมผู้เชี่ยวชาญหลายปี agent ตรวจงานตัวเองและส่งราว 1% ให้มนุษย์ตรวจ ที่เหลือ Lean ตรวจอัตโนมัติ จุดสำคัญคือบทพิสูจน์ครอบคลุมถึงโค้ดที่คอมไพล์แล้วระดับคำสั่งเครื่อง ไม่ใช่แค่การออกแบบโปรโตคอล ทีมยังทดสอบด้วยการใส่บั๊กเก่าสองตัวกลับเข้าไป และระบบสร้างบทพิสูจน์ได้ว่าเวอร์ชันนั้นไม่ปลอดภัย Ehren Kret CTO ของ Signal เรียกว่าเป็นก้าวสำคัญ DeepMind วางแผนเปิดซอร์ส artifact และต่อยอดกับ CodeMender ซึ่งอาจขยายไปสู่เฟิร์มแวร์อุปกรณ์การแพทย์และซอฟต์แวร์ระบบไฟฟ้า

Introducing the Multimodal Knowledge Agent benchmark
Google และ Artificial Analysis เปิดตัว benchmark MKA วัด agent งานความรู้แบบมัลติโมดัล
Google DeepMind ร่วมกับ Artificial Analysis เปิดตัว benchmark ชื่อ Multimodal Knowledge Agent (MKA) เพื่อวัดความสามารถของ AI agent ในการทำงานความรู้จริงที่ต้องอ่านไฟล์ภาพซับซ้อน เช่น แบบแปลน แผนผัง สไลด์ รายงาน และสเปรดชีต ผู้เขียนชี้ว่า benchmark งานความรู้ส่วนใหญ่แก้ได้จากข้อความล้วน ชุดประเมินมี 200 งานจาก 10 กลุ่มอุตสาหกรรมและ 83 อาชีพ แต่ละงานเป็นโปรเจกต์หลายขั้นตอนที่มืออาชีพใช้เวลา 3-8 ชั่วโมง มีรูบริกราว 70 ข้อแบบใช่หรือไม่ ให้น้ำหนักความถูกต้องของข้อเท็จจริง 75% และการออกแบบภาพ 25% การให้คะแนนใช้ agentic autorater ที่สร้างบนโมเดลที่ไม่ใช่ของ Google และเห็นตรงกับผู้เชี่ยวชาญ 96% ทุกโมเดลรันใน harness โอเพนซอร์สชื่อ Stirrup ด้วยเครื่องมือและงบรอบเท่ากัน ชุดหลักเก็บเป็นความลับเพื่อกันข้อมูลรั่วเข้าการฝึก และมีงานสาธารณะ 10 งานบน Hugging Face ผลพบว่าโมเดลใช้ 30-130 รอบต่องาน และเมื่อตัดความสามารถด้านภาพออกจะล้มเหลว Gemini 4 Carbon ได้อันดับ 2 ด้านคุณภาพโดยต้นทุนต่ำกว่าอันดับ 1 ราว 6 เท่า แม้ benchmark นี้ Google เป็นผู้ร่วมสร้างจึงควรอ่านผลอย่างระมัดระวัง

Test-Time Compute Scales Better with Parallel Agent Teams
งานวิจัยชี้การขยาย test-time compute ด้วยทีม agent ขนาดเล็กหลายทีมขนานกันได้ผลดีกว่า
งานวิจัยบน arXiv โดย Junlin Wang, Haozhe Chen, Ang Li, Rahul Chalamala และ Zhuang Liu ศึกษาวิธีใช้ test-time compute ให้คุ้มค่าเมื่อมีตัวตรวจ (verifier) ให้คะแนนผลลัพธ์ได้ทุกครั้ง วิธีทั่วไปมีสองแบบ คือ Best-of-N ที่รัน agent อิสระจำนวนมากแล้วเลือกผลดีที่สุดซึ่งได้ประโยชน์ลดลงเร็ว และการใช้ทีม agent ใหญ่ทีมเดียวที่ทำคะแนนสูงกว่าแต่หยุดพัฒนาเมื่อขยายขนาด ผู้วิจัยเสนอ parallel agent teams คือรันทีมเล็กหลายทีมพร้อมกันแล้วเลือกผลของทีมที่ดีที่สุด ทดสอบกับงานระยะยาว 12 งาน เช่น การพัฒนา GPU kernel การพิสูจน์เชิงรูปนัย และการพัฒนา exploit เมื่อใช้โมเดลขนาด 27B และงบ 100 agent ทีมละ 10 ตัวชนะ agent อิสระได้ 10 จาก 12 งาน และชนะทีมเดียว 100 ตัวในทั้ง 4 งานที่ทดสอบ เมื่อเทียบที่ต้นทุนดอลลาร์เท่ากันยังชนะโมเดล frontier ได้ครึ่งหนึ่งของงาน โมเดลสถิติอย่างง่ายอธิบายว่า agent อิสระมีค่าเฉลี่ยต่ำ ส่วนทีมใหญ่ไม่ได้ประโยชน์จากความแปรปรวน ทีมเล็กหลายทีมจึงสมดุลทั้งสองด้าน ข้อค้นพบนี้สอดคล้องกับฟีเจอร์ swarm ที่ผู้ให้บริการโมเดลเริ่มนำมาใช้

งานวิจัยบน arXiv โดย Ayush Sawarni, Wenqian Xing, Tijana Zrnic, Ramesh Johari และ Vasilis Syrgkanis ชี้ว่าการประเมิน agentic AI ในปัจจุบันพึ่ง benchmark แบบคงที่เป็นหลัก ซึ่งแทบไม่บอกว่าการแทรกแซงระหว่างใช้งานจริง เช่น การตรวจผลลัพธ์ของ agent การปรับพฤติกรรม การส่งให้มนุษย์ตรวจ หรือการเรียกโมเดลที่แพงกว่า ช่วยได้จริงหรือไม่ ผู้วิจัยจึงมองคุณค่าของการแทรกแซงเป็นปัญหา causal inference ซึ่งยากเพราะผลของการแทรกแซงขึ้นกับบริบท สภาพแวดล้อม และพฤติกรรมในอนาคตของ agent งานนี้เสนอสิ่งที่ผู้เขียนเรียกว่ากรอบแรกที่มีหลักการทางระเบียบวิธี สำหรับประเมินผลเชิงเหตุของการแทรกแซงแบบสุ่มภายใน trajectory ของ agent โดยใช้ชุดข้อมูล trajectory ขนาดไม่ใหญ่ที่เก็บภายใต้การแทรกแซงแบบสุ่ม และสามารถนำพารามิเตอร์ที่ประมาณได้ไปสร้าง safety leaderboard จัดอันดับความเสี่ยงของการกระทำแต่ละแบบ เพื่อจัดลำดับความสำคัญในการตรวจสอบ เมื่อทดลองกับ tau-bench Retail, ToolSandbox และ ImpossibleBench พบว่าผลของการแทรกแซงแตกต่างกันมากตามการกระทำและสถานะ งานนี้สำคัญในช่วงที่รัฐและบริษัทต่างเร่งหากลไกควบคุม agent เช่น หน่วยงานกำกับของออสเตรเลียและ Control Room ของ OpenAI
