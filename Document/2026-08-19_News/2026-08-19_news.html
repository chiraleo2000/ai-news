Meet SAM (Sovereign Agent Mesh): A Zero-Config, Zero-Trust P2P Network for AI Agents
Google เปิดโอเพนซอร์ส SAM เครือข่าย P2P แบบ Zero-Trust สำหรับ AI Agent
Google เปิดโอเพนซอร์สโปรเจกต์ SAM หรือ Sovereign Agent Mesh ภายใต้สัญญาอนุญาต Apache-2.0 เป็นเครือข่าย P2P แบบ zero-config และ zero-trust สำหรับ AI agent ที่ทำงานกระจายบนคลาวด์ ศูนย์ข้อมูล แล็ปท็อป และอุปกรณ์ Android ปัญหาที่แก้ไขคือการแชร์เครื่องมือระหว่าง agent มักต้องเปิดเผย API ส่วนตัวสู่อินเทอร์เน็ต SAM ทำหน้าที่คล้าย VPN ส่วนตัวที่จำกัดเฉพาะการแชร์เครื่องมือผ่าน Model Context Protocol โหนดค้นหากันเองอัตโนมัติ ทำงานผ่าน NAT ได้ และตรวจสอบสิทธิ์ทุกการเรียกด้วยการเข้ารหัส ระบบใช้สถาปัตยกรรมสามส่วนคือ control plane, router และ node จุดเด่นคือการแปลง OIDC JWT เป็น Biscuit token ให้ตรวจสอบสิทธิ์แบบออฟไลน์ได้ โดยมีค่าเริ่มต้นปฏิเสธการเข้าถึงทั้งหมด เหมาะสำหรับองค์กรควบคุมเข้มงวดเช่นการเงินและสาธารณสุข Google เปิดโอเพนซอร์สโปรเจกต์เครือข่ายชื่อ SAM หรือ Sovereign Agent Mesh (ไม่ใช่ Segment Anything Model) ภายใต้สัญญาอนุญาต Apache-2.0 สำหรับ AI agent ที่ทำงานอย่างอิสระ ปัญหาที่โปรเจกต์นี้มุ่งแก้ไขคือ agent ในปัจจุบันทำงานกระจายอยู่บนเซิร์ฟเวอร์คลาวด์ ศูนย์ข้อมูลภายในองค์กร แล็ปท็อป Raspberry Pi และอุปกรณ์ Android การให้ agent เหล่านี้แชร์เครื่องมือกันมักหมายถึงการต้องเปิดเผยสคริปต์ภายใน endpoint ของโมเดลภาษา หรือ API ส่วนตัวสู่อินเทอร์เน็ตสาธารณะ ทางเลือกของ SAM คือการสร้างโครงข่ายซ้อนทับแบบ P2P ที่ไม่ต้องตั้งค่าและเป็น zero-trust ใกล้เคียงกับ VPN ส่วนตัว แต่จำกัดขอบเขตเฉพาะการแชร์เครื่องมือระหว่าง agent ผ่าน Model Context Protocol โดยโหนดค้นหากันเองโดยอัตโนมัติ ทำงานผ่าน NAT ได้ และตรวจสอบสิทธิ์ทุกการเรียกด้วยวิธีเข้ารหัส ทั้งนี้ repository มีข้อความปฏิเสธชัดเจนว่านี่ไม่ใช่ผลิตภัณฑ์ที่ Google รองรับอย่างเป็นทางการ ในแง่สถาปัตยกรรม ระบบประกอบด้วยสามไบนารีหลัก ได้แก่ sam-control-plane ทำหน้าที่ลงทะเบียนตัวตน ออก token และกระจายนโยบาย sam-router ทำหน้าที่เป็นจุดเริ่มต้น libp2p และเส้นทาง GossipRoute ส่วน sam-node เป็นไคลเอนต์ P2P ที่ให้บริการขนส่งเครือข่าย การเชื่อมต่อที่ซ่อมแซมตัวเองได้ และ MCP HTTP interface ในเครื่อง จุดเด่นทางเทคนิคที่น่าสนใจคือการยืนยันตัวตน โดย control plane จะตรวจสอบ OIDC JWT แล้วแปลงเป็น Datalog facts และปิดผนึกเป็น Biscuit

NVIDIA Releases TensorRT Model Connect in Public Preview: Hugging Face Checkpoint to Native C++ Inference in Two Commands
NVIDIA เปิดตัว TensorRT Model Connect แปลงโมเดลเป็น C++ Inference ได้ในสองคำสั่ง
NVIDIA เปิดตัวโปรเจกต์โอเพนซอร์ส TensorRT Model Connect หรือ TRTMC ในรูปแบบพรีวิวสาธารณะ ช่วยแปลงโมเดลจาก Hugging Face หรือไฟล์ในเครื่องไปเป็น inference แบบ TensorRT บน C++ ได้ภายในสองคำสั่ง โดยไม่ต้องผ่านขั้นตอนแปลงเป็น ONNX แบบเดิม ระบบสร้างไฟล์ artifact แบบมีเวอร์ชันเรียกว่า .bundle ที่ทำงานผ่าน task API แบบเนทีฟบน C++ ทำให้รัน inference ในบริการ C++ แอปพลิเคชันฝังตัว หรือระบบหุ่นยนต์ได้โดยไม่ต้องพึ่ง PyTorch ในรันไทม์ โปรเจกต์ใช้สัญญาอนุญาต Apache-2.0 และ NVIDIA ระบุว่าทั้งโปรเจกต์ถูกสร้างขึ้นโดยใช้ OpenAI Codex agents ภายใต้การกำกับดูแลของมนุษย์ ปัจจุบันรองรับเฉพาะ Linux aarch64 เหมาะสำหรับทีมที่เป็นเจ้าของ stack inference เอง เช่น สตาร์ทอัพ NVIDIA บริษัทหุ่นยนต์ และทีมแพลตฟอร์มในองค์กรขนาดกลางถึงใหญ่ NVIDIA เปิดตัว TensorRT Model Connect (TRTMC) ในรูปแบบพรีวิวสาธารณะ เป็นโปรเจกต์โอเพนซอร์สที่นำโมเดลจาก Hugging Face หรือไฟล์ checkpoint ในเครื่องที่รองรับไปสู่ inference แบบ TensorRT แบบครบวงจรได้ภายในสองคำสั่ง โดยไม่มีขั้นตอนกลางที่ต้องแปลงเป็น ONNX เหมือนวิธีดั้งเดิม กระบวนการสร้างจะได้ไฟล์ artifact ที่มีเวอร์ชันเรียกว่า .bundle ซึ่งทำงานผ่าน native C++ task API ทำให้สามารถรัน inference ในบริการ C++ แอปพลิเคชันฝังตัว หรือ stack หุ่นยนต์ได้โดยไม่ต้องมี PyTorch อยู่ใน runtime path โปรเจกต์นี้ใช้สัญญาอนุญาต Apache-2.0 และมาในรูปแบบชุด implementation อ้างอิงที่เป็นเจ้าของเฉพาะแต่ละตระกูลโมเดล มากกว่าจะเป็นตัวแปลงทั่วไปตัวเดียว NVIDIA ยังระบุด้วยว่าทั้งโปรเจกต์ ตั้งแต่การพัฒนาโมเดล การปรับแต่งประสิทธิภาพ การทดสอบ การเชื่อมต่อระบบ ไปจนถึงเอกสารประกอบ ถูกสร้างขึ้นโดยใช้ OpenAI Codex agents ภายใต้การกำกับดูแลของมนุษย์ ในแง่ความพร้อมใช้งาน โค้ดเปิดเผยและติดตั้งได้แล้วสำหรับการประเมินและงานเชื่อมต่อแบบเนทีฟ แต่มีเงื่อนไขจริงคือไฟล์ wheel รุ่นปัจจุบันรองรับเฉพาะ Linux aarch64 พร้อม Python 3.10 หรือ 3.12, glibc 2.39 ขึ้นไป และ TensorRT 11.1.0.106 เท่านั้น ยังไม่มีการเผยแพร่ไฟล์ wheel สำหรับ x86_64 ผู้ใช้ที่ใช้สถาปัตยกรรมนี้ต้องสร้างผ่าน Docker กลุ่มเป้าหมายที่เหมาะสมที่สุดคือทีมที่เป็นเจ้าของ stack inference ของตนเองอยู่แล้ว เช่น สตาร์ทอัพที่ใช้ฮาร์ดแวร์ NVIDIA
