On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification
ความเปราะบางของ AI Agent ที่พัฒนาตัวเองได้: ความแปรปรวน ลำดับงาน และข้อมูลที่ไม่ครบถ้วน
AI agent แบบ self-improving ที่เรียนรู้จากงานต่อเนื่องและพัฒนาความสามารถผ่านความจำแบบข้อความเป็นแนวทางที่ได้รับความสนใจสูง แต่ทีมวิจัยจาก Salesforce AI Research ชี้ว่าความน่าเชื่อถือของวิธีการเหล่านี้ถูกมองข้าม งานวิจัยนี้ประเมินวิธี memory-based สองวิธีซ้ำอย่างละเอียด เพิ่มการทดลองหลายรอบเพื่อวัดความแปรปรวน และสลับลำดับงานแบบสุ่มเพื่อดูผลกระทบ พบสองข้อสังเกตสำคัญคือ การประเมิน agent ผันผวนสูงตามธรรมชาติในสภาพแวดล้อมซับซ้อนและงานหลายขั้นตอน และการวนซ้ำแบบพัฒนาตัวเองยิ่งขยายความผันผวนนี้ อีกทั้งการพัฒนาของ agent ยังขึ้นอยู่กับลำดับงานอย่างมาก งานก่อนหน้ามักใช้ลำดับตายตัวที่สร้างหลักสูตรแฝงโดยไม่รู้ตัว ทีมวิจัยพบว่าการเพิ่มข้อมูลรายละเอียด เช่น เกณฑ์การให้คะแนนและผลตอบรับจากสภาพแวดล้อม เข้าไปในความจำ ช่วยลดปัญหาได้บางส่วนแต่ยังมีช่องว่างสำคัญเหลืออยู่ AI agent แบบ memory-based self-improving ที่เรียนรู้จากกระแสงานแบบออนไลน์และพัฒนาตัวเองอย่างต่อเนื่องด้วยการรักษาคลังความจำแบบข้อความ ได้รับการยกย่องว่ามีศักยภาพสูงในงานวิจัยที่ผ่านมา แต่ทีมวิจัยจาก Salesforce AI Research ชี้ว่าประเด็นความน่าเชื่อถือของวิธีการเหล่านี้ถูกมองข้ามอย่างวิกฤต ทีมวิจัยจึงดำเนินการประเมินซ้ำอย่างครอบคลุมกับวิธีการแบบ memory-based สองวิธี โดยขยายขอบเขตการประเมินด้วยสองแนวทางคือ การทดลองหลายรอบเพื่อวัดค่าความแปรปรวน และการสลับลำดับงานแบบสุ่มเพื่อตรวจสอบผลกระทบของลำดับต่อผลลัพธ์ จากการทดลองพบข้อสังเกตสำคัญสองประการที่เผยให้เห็นความเปราะบางของวิธีการปัจจุบัน ประการแรก การประเมิน agent มีความผันผวนสูงตามธรรมชาติในสภาพแวดล้อมที่ซับซ้อนและงานที่มีหลายขั้นตอน และการซ้อนวงจรการพัฒนาตัวเองไว้ด้านบนยิ่งขยายความผันผวนนี้มากขึ้นไปอีก ประการที่สอง การพัฒนาของ agent ขึ้นอยู่กับลำดับงานอย่างมาก งานวิจัยก่อนหน้ามักใช้ลำดับตายตัวที่สร้างหลักสูตรแฝงโดยไม่ตั้งใจ ซึ่งกลายเป็นเงื่อนไขซ่อนเร้นที่จำเป็นต่อความสำเร็จของวิธีการ เพื่อทำความเข้าใจความเปราะบางนี้ให้ลึกขึ้น OpenAI ยืนยันคำมั่นสัญญาด้านนโยบาย Zero Data Retention หรือ ZDR สำหรับลูกค้า API ที่มีสิทธิ์ โดยรับประกันว่าจะไม่เก็บคำสั่งหรือคำตอบของโมเดลหลังจากประมวลผลคำขอเสร็จสิ้น พร้อมเปิดตัวเทคโนโลยีใหม่ชื่อ Private Safety Processing ซึ่งอยู่ระหว่างทดสอบกับลูกค้ากลุ่มแรก ระบบนี้ออกแบบมาเพื่อระบุรูปแบบความเสี่ยงที่ปรากฏข้ามหลายการสนทนา โดยไม่ต้องให้พนักงาน OpenAI เข้าถึงเนื้อหาต้นฉบับ เนื่องจากความเสี่ยงร้ายแรงด้านเอไอมักไม่ปรากฏชัดในการสนทนาเดียว แต่จะเห็นได้ชัดเมื่อพิจารณาหลายการสนทนาร่วมกัน เช่น ผู้ไม่หวังดีที่พยายามหลบเลี่ยงระบบตรวจจับหรือเอเจนต์ที่เริ่มทำงานเบี่ยงเบนจากเจตนาของผู้ใช้ ข้อมูลลูกค้าจะถูกเข้ารหัสด้วยกุญแจที่ลูกค้าควบคุมเอง เมื่อพบความเสี่ยง OpenAI จะได้รับเพียงสัญญาณเตือนที่กำหนดขอบเขตแคบโดยไม่เห็นเนื้อหาจริง องค์กรอย่าง Glean, Databricks, Abridge และ Microsoft ร่วมให้ข้อเสนอแนะในการพัฒนาระบบนี้ โดย OpenAI GxP-Agent: Process-DAG Topology for Reliable Clinical Trial Programming with LLM Agents

การเขียนโปรแกรมแปลงข้อมูลทดลองทางคลินิกให้เป็นชุดข้อมูลตามมาตรฐาน CDISC เป็นคอขวดของกระบวนการยื่นเอกสารกำกับดูแล และโมเดลภาษาขนาดใหญ่แบบเดี่ยวล้มเหลวอย่างสิ้นเชิง จากการทดสอบ 11 OpenAI ประกาศระบบใหม่ชื่อ Private Safety Processing ซึ่งเป็นระบบอัตโนมัติที่ตรวจจับการใช้งานในทางที่ผิดข้ามหลายเซสชันการสนทนา โดยไม่ต้องเก็บข้อมูลของลูกค้าไว้ให้พนักงาน OpenAI เข้าถึงได้ ระบบนี้ต่อยอดจากนโยบาย Zero Data Retention เดิมที่ตรวจสอบเพียงเซสชันเดียว การเคลื่อนไหวนี้ถือเป็นการท้าทายนโยบายของ Anthropic ที่ประกาศเมื่อเดือนกรกฎาคมว่าจะเก็บข้อมูลการสนทนาของโมเดลบางรุ่นไว้นานถึง 30 วันเพื่อเหตุผลด้านความปลอดภัย ซึ่งสร้างความกังวลให้กับองค์กรที่จัดการข้อมูลอ่อนไหว เมื่อระบบของ OpenAI ตรวจพบความเสี่ยง จะส่งสัญญาณเตือนแบบจำกัดขอบเขตไปยังบริษัทโดยไม่เปิดเผยเนื้อหาการสนทนา การแข่งขันระหว่างสองบริษัทกำลังทวีความเข้มข้น ท่ามกลางรายงานว่ารายได้ของ Anthropic เติบโตเร็วกว่า OpenAI ในไตรมาสล่าสุด และทั้งคู่ต่างเตรียมแผนเข้าตลาดหลักทรัพย์ในอนาคต OpenAI ประกาศเมื่อวันที่ 19 สิงหาคม 2026 เปิดตัวระบบ Private Safety Processing ซึ่งเป็นเทคโนโลยีตรวจจับการใช้งานในทางที่ผิดแบบข้ามเซสชัน โดยไม่ต้องให้พนักงาน OpenAI เข้าถึงเนื้อหาการสนทนาของลูกค้า ระบบนี้ขยายขอบเขตจากนโยบาย Zero Data Retention (ZDR) เดิม ซึ่งตรวจสอบเพียงทีละเซสชัน การเคลื่อนไหวนี้เกิดขึ้นเพื่อตอบโต้นโยบายของ Anthropic ที่ประกาศเมื่อเดือนกรกฎาคมว่าจะเก็บข้อมูลการสนทนาของโมเดลระดับ "covered models" เช่น Fable ไว้นาน 30 วัน ซึ่งสร้างความไม่พอใจให้กับองค์กรที่ต้องจัดการข้อมูลอ่อนไหว เช่น ข้อมูลการเงินและสุขภาพ เมื่อระบบของ OpenAI ตรวจพบพฤติกรรมต้องสงสัย เช่น ผู้ไม่หวังดีที่พยายามพัฒนามัลแวร์โดยแบ่งคำขอออกเป็นหลายเซสชันเพื่อหลบเลี่ยงการตรวจจับ ระบบจะส่ง "สัญญาณที่กำหนดขอบเขตแคบ" ไปยัง OpenAI เพื่อพิจารณาว่าจำเป็นต้องดำเนินการหรือไม่ โดยไม่เปิดเผยเนื้อหาการสนทนาให้พนักงานเห็น ลูกค้าสามารถเลือกแบ่งปันข้อมูลเพิ่มเติมได้เองหากต้องการอุทธรณ์ การแข่งขันระหว่าง OpenAI และ Anthropic ทวีความเข้มข้นขึ้น ท่ามกลางรายงานว่ารายได้ต่อปีของ Anthropic พุ่งแตะ 6.5 หมื่นล้านดอลลาร์ ขณะที่ยอดขายไตรมาสสองของ OpenAI เติบโตช้ากว่าคู่แข่ง ทั้งสองบริษัทต่างเตรียมแผนเข้าตลาดหลักทรัพย์ในอนาคต OpenAI เปิดตัวระบบ Private Safety Processing เพื่อตรวจจับการใช้งานในทางที่ผิดโดยไม่เก็บข้อมูลลูกค้า ท้าทายนโยบายเก็บข้อมูล 30 วันของ Anthropic
